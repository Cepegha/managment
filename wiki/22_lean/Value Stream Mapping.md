# Value Stream Mapping

Инструмент визуализации всего потока создания ценности — от получения заявки до доставки ценности клиенту. Показывает, где в потоке есть потери.

## Core Principle

Нарисовать весь процесс как он есть (Current State Map), затем спроектировать как должно быть (Future State Map). Разница между картами — программа улучшений.

## Что отображает VSM

- Все шаги процесса (операции, передачи, ожидания)
- Время выполнения каждого шага
- Время ожидания между шагами
- Запасы (буферы) между шагами
- Информационные потоки
- Соотношение: время добавления ценности / общее время (Lead Time)

## Процесс построения

1. Выбрать поток (продукт/услуга/семейство)
2. Нарисовать Current State Map (текущее состояние)
3. Найти потери ([[Muda]]): ожидание, запасы, переделки
4. Спроектировать Future State Map (целевое состояние)
5. Составить план перехода (Kaizen Events, [[PDCA]])

## VSM в дистрибьюции

**Пример потока: «Заявка клиента → Доставка»**

```
Клиент → Приём заявки → Резервирование → Сборка → Проверка → Отгрузка → Доставка → Клиент
```

Типичные потери, которые выявляет VSM:

- Ожидание подписи руководителя (Muda: Waiting)
- Двойной ввод данных в две системы (Muda: Overprocessing)
- Переборка неправильно собранного заказа (Muda: Defects)
- Товар пришедший не туда (Muda: Transportation)
